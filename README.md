# StreamShelf

A streaming app for phones (iOS, Android) and TVs (tvOS, Android TV, Fire TV), built with Expo,
React Native (`react-native-tvos`), and TypeScript. It browses live channels from
[iptv-org](https://github.com/iptv-org/iptv).

## Requirements

- Node 22.13+ (`nvm use` reads `.nvmrc`)
- npm 10 (the version is pinned in `packageManager`)

## Setup

```sh
nvm use
npm install
```

The apps use [development builds](https://docs.expo.dev/develop/development-builds/introduction/)
(`expo-dev-client`), not Expo Go: Expo Go can't load `react-native-tvos` or custom native modules.
Native folders (`ios/`, `android/`) are generated by `expo prebuild` and are never committed.

Running locally needs Xcode (iOS and tvOS simulators) and/or Android Studio (an emulator).

If the app fails at runtime with `Cannot find native module '…'` after dependency changes, npm has
probably nested an Expo module inside another package (e.g. `node_modules/expo/node_modules/`),
where autolinking doesn't look. Reinstall from scratch, including the workspace folders, then
rebuild:

```sh
find . -name node_modules -type d -prune -exec rm -rf {} +
rm -f package-lock.json
npm install
```

## Running

Each command builds the native app, installs it on a simulator/emulator, and starts Metro.

| Target               | Command                             |
| -------------------- | ----------------------------------- |
| iOS phone/tablet     | `npm run ios -w apps/mobile`        |
| Android phone/tablet | `npm run android -w apps/mobile`    |
| tvOS                 | `npm run ios -w apps/native-tv`     |
| Android TV / Fire TV | `npm run android -w apps/native-tv` |

Pass a device with `-- --device "<name>"` (e.g. `"Apple TV 4K (3rd generation)"`). For Fire TV,
connect with `adb connect <fire-tv-ip>` first; it then shows up as an Android device.

Build one iOS/tvOS app at a time: both apps compile `expo-modules-jsi` into the same hoisted
`node_modules` folder, so two simultaneous `xcodebuild`s collide (`build.db: disk I/O error`).

After changing `app.config.ts`, a config plugin or a native dependency, regenerate the native
projects with `npm run prebuild -w <workspace>` (always `--clean`; switching between phone and TV
builds without it breaks CocoaPods).

### Build variants

`APP_VARIANT` (`development` by default, `preview`, `production`) sets the app name and bundle
ID, so all three can be installed side by side:

| Variant       | Mobile bundle ID                    | TV bundle ID                           |
| ------------- | ----------------------------------- | -------------------------------------- |
| `development` | `com.cjensen99.streamshelf.dev`     | `com.cjensen99.streamshelf.tv.dev`     |
| `preview`     | `com.cjensen99.streamshelf.preview` | `com.cjensen99.streamshelf.tv.preview` |
| `production`  | `com.cjensen99.streamshelf`         | `com.cjensen99.streamshelf.tv`         |

EAS profiles in each app's `eas.json` set it (`development`, `development-simulator`,
`preview`, `production`).

## Testing

- **`shared/`** uses Jest (`jest-expo`) with React Native Testing Library. Tests live in
  `shared/__tests__/`. Every test runs twice, as two Jest projects: **tv** resolves files like
  the TV app (TV-first defaults) and **mobile** like the phone app (`Foo.mobile.tsx` first), so a
  phone-only override can't go untested. Run one project with
  `npm test -w shared -- --selectProjects mobile`.
- **`config/`** (Node build-time code) uses Node's built-in test runner. The UIScene plugin is
  tested against copies of Expo's real SDK 57 and SDK 58 native templates
  (`config/__tests__/fixtures/`).

## Repository layout

```
apps/
  mobile/      iOS and Android phones and tablets
  native-tv/   tvOS, Android TV, Fire TV (built with EXPO_TV=1)
shared/        "@app/shared": all runtime app code (bundled into the apps)
config/        "@app/config": build-time configuration (Node only, never bundled)
  brand.json   app name, bundle-ID base, brand colours
  variant.js   APP_VARIANT parsing; name and bundle-ID suffixes per variant
  expo/        Expo config shared by the native apps (policy.js) and config plugins (plugins/)
  metro/       createMetroConfig: Expo's default config + per-app platform extensions
assets/        app icons, splash, Android TV banner, tvOS brand assets (placeholders for now)
```

npm workspaces link `shared/` and `config/` into `node_modules/@app/*`, so code imports them by
package path, such as `@app/shared/api/client` or `@app/config/expo/policy`. The repo has no path
aliases and no barrel files: every import names the module it needs.

Each app's `app.config.ts` keeps what makes that app different (name, bundle ID, orientation,
TV plugin and assets) and takes everything that must stay identical (network policy, icons,
splash, common plugins, variants) from `@app/config`. `@app/config` is CommonJS JavaScript with
`// @ts-check` and JSDoc types, because Expo loads app-config imports with plain Node `require`,
which can't load TypeScript from another package; `npm run typecheck` checks it.

Shared code is TV-first: `Foo.tsx` is the TV version, and `Foo.mobile.tsx` overrides it in the
phone app only (the phone app's Metro config and `tsconfig.json` `moduleSuffixes` resolve it).

## Conventions

ESLint enforces these rules (`eslint.config.js`):

| Import                                                                           | Allowed only in                                       |
| -------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `react-tv-space-navigation`                                                      | `shared/focus/`                                       |
| `react-native-video`                                                             | `shared/player/`                                      |
| `TVEventHandler`, `useTVEventHandler`, `BackHandler`, `TVEventControl` (from RN) | `shared/input/`                                       |
| `zustand`                                                                        | `shared/state/`                                       |
| `@tanstack/react-query`                                                          | `shared/api/`, `shared/hooks/`                        |
| `@react-native-async-storage/async-storage`, `@react-native-community/netinfo`   | `shared/utils/` (wrapped by `storage`, `network`)     |
| `react-native` (any import)                                                      | anywhere **except** `shared/api/` and `shared/types/` |
| Raw hex colours                                                                  | `shared/ui/`                                          |

`shared/__tests__/` is exempt from the import rules so tests can set up and mock any layer.
`react-hooks/exhaustive-deps` is an error.

## Known limitations

- **Dev menu app icon is blank on iOS/tvOS (development builds only).** App icons live in the
  root `assets/` folder, outside each app's project root. Expo's dev server builds the manifest
  icon URL as `/assets/../../assets/icon.png`, which collapses to the wrong path (Metro logs
  `Asset not found: apps/<app>/icon.png`). The real app icons are embedded natively by `prebuild`
  and are unaffected.

## Decisions

- **Expo SDK 57 (React Native 0.86, React 19.2): the newest SDK with stable React Native and
  `react-native-tvos` releases.** SDK 53 (first choice) doesn't compile with Xcode 27. SDK 58 works
  with Xcode 27 out of the box but is built on React Native 0.88 release candidates.
- **UIScene config plugin (`config/expo/plugins/withSceneLifecycle.js`).** Apps built with Xcode 27 are
  terminated at launch on iOS/tvOS 27 unless they use the UIScene life cycle. SDK 57 already ships
  Expo's scene delegate (`ExpoAppSceneDelegate`), but its prebuild template doesn't use it. The
  plugin applies SDK 58's template change: a scene manifest in `Info.plist`, an empty
  `SceneDelegate` subclass, and an `AppDelegate` that no longer creates its own window. It fails
  `prebuild` with a clear error if the template changes. Delete it when upgrading to SDK 58+.
- **`react-native-tvos` in both apps.** One React Native fork (`npm:react-native-tvos@0.86.3-0`)
  serves phones and TVs, so `shared/` compiles against a single RN version.
- **`legacy-peer-deps=true` (`.npmrc`).** `react-native-tvos` versions are semver prereleases,
  which never satisfy library peer ranges like `>=0.65 <1.0`, so npm refuses to install them.
  `overrides` doesn't help because npm doesn't apply it to peer checks. Consequence: npm no longer
  auto-installs peers, so each app lists every native dependency explicitly, and
  `expo install --check` and `expo-doctor` verify versions instead.
- **`expo.install.exclude: ["react-native"]`** stops Expo from "fixing" the fork back to stock
  React Native.
- **Cleartext media.** Many iptv-org streams are `http://`. iOS/tvOS allow it for media only
  (`NSAllowsArbitraryLoadsForMedia`). Android has no media-only switch, so
  `usesCleartextTraffic` is app-wide; API calls still use HTTPS.
- **Separate `@app/config` package for build-time code.** `@app/shared` stays purely runtime code
  that Metro (and later react-native-web) bundles; Node-only code (app config, config plugins,
  Metro config) lives in `@app/config`, linted and type-checked as Node. Unlike orkaTV-style path
  aliases, package imports need no Babel, Metro, webpack or `tsconfig` alias lists to keep in sync.
- **Fire TV** uses the Android TV build: leanback and touchscreen are declared as not required,
  so the same APK installs on Fire TV, Android TV and Google TV.
